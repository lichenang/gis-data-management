# Proposal: fix-srs-epsg-code

## 问题描述

影像上传后，SRS（空间参考系统）存储为非标准格式，导致后续 CRS 转换失败。

例如：
- **期望格式**: `EPSG:3857` 或 `EPSG:4326`
- **实际存储**: `EPSG:WGS 84 / Pseudo-Mercator`

这导致 CrsTransformUtil 在进行坐标转换时无法解析坐标系。

## 根因分析

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        问题根因                                          │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  GeoTiffParser.extractCrs() 返回值分析                                   │
│                                                                         │
│  ┌──────────────────────────────────────────────────────────────────┐  │
│  │ try {                                                            │  │
│  │     getIdentifiers() → 获取 EPSG 代码                            │  │
│  │     ├─ 成功 → code = "EPSG:3857" ✓                              │  │
│  │     └─ 失败 → 进入 fallback                                    │  │
│  │                                                                  │  │
│  │     getName() → 返回自然语言描述                                  │  │
│  │     └─ code = "EPSG:WGS 84 / Pseudo-Mercator" ✗                │  │
│  │ }                                                                │  │
│  └──────────────────────────────────────────────────────────────────┘  │
│                                                                         │
│  CRS 转换失败原因: CrsTransformUtil 无法解析自然语言描述                 │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

代码位置: `GeoTiffParser.java:164-197`

## 修复方案

修改 `GeoTiffParser.extractCrs()` 方法，使用 GeoTools API 正确提取 EPSG 代码：

1. 优先从 `getIdentifiers()` 获取 EPSG 代码
2. 如果获取失败，尝试使用 `CRS.lookupHorizontalCRS()` 查找
3. 返回标准格式: `EPSG:3857` 或 `EPSG:4326`

## 影响范围

- 修改: `GeoTiffParser.java` - extractCrs() 方法

## 风险评估

- 低风险：仅修改 SRS 提取逻辑，不改变业务逻辑
